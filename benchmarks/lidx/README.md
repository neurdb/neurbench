# indexBench - A Benchmark for Learned Indexes in drifted workload

This project is developed based on TLI (Testbed for Learned Indexes) to investigate the performance of learned index in complex drifted workload.
We refactor and reuse part of basic functions in TLI, and add new features to support drifted workload.


## Dependencies

One dependency that should be emphasized is [Intel MKL](https://software.intel.com/en-us/mkl), used when testing the performance of [XIndex and SIndex](https://ipads.se.sjtu.edu.cn:1312/opensource/xindex). The detailed steps of installation can be found [here](https://software.intel.com/en-us/articles/installing-intel-free-libs-and-python-apt-repo).



Generally, the dependencies can be installed and manually set in `CMakeLists.txt` as follows.
```cmake
set(MKL_INCLUDE_DIRECTORY "/users/guoyu/intel/oneapi/mkl/2024.0/include")
set(MKL_LINK_DIRECTORY "/users/guoyu/intel/oneapi/mkl/2024.0/lib")

set(TBB_INCLUDE_DIRECTORY "/users/lingze/intel/oneapi/tbb/2021.13/include")
set(TBB_LINK_DIRECTORY "/users/lingze/intel/oneapi/tbb/2021.13/lib")

set(JEMALLOC_INCLUDE_DIRECTORY "/users/lingze/cpp_pkg/jemalloc-5.3.0/include/jemalloc")
set(JEMALLOC_LINK_DIRECTORY "/users/lingze/cpp_pkg/jemalloc-5.3.0/lib")
```

then compile the project with the following commands.


```shell
git submodule update --init --recursive 

mkdir -p build
cd build
cmake -DCMAKE_BUILD_TYPE=Release ..
make -j 256
```

As for the dataset, we recommend to manually download related datasets from the following links.
- fb_200M_uint64: [Facebook's dataset](https://dataverse.harvard.edu/api/access/datafile/:persistentId?persistentId=doi:10.7910/DVN/JGVF9A/EATHF7)
- wiki_ts_200M_uint64: [Wikipedia's dataset](https://dataverse.harvard.edu/api/access/datafile/:persistentId?persistentId=doi:10.7910/DVN/JGVF9A/SVN8PI)
- osm_cellids_800M_uint64: [OpenStreetMap's dataset](https://www.dropbox.com/s/j1d4ufn4fyb4po2/osm_cellids_800M_uint64.zst?dl=1)
- books_800M_uint64: [Books' dataset](https://www.dropbox.com/s/y2u3nbanbnbmg7n/books_800M_uint64.zst?dl=1)



## Workload Generation
We provide several scripts to automate the test process.

First is to generate the drifted workload associated the `drifted_generate` execution file
In this script, we need to assign <bulkloading_data> and <insert_data> two data file paths, which are generated by preprocessing part in `neuralbench` repo first.


some example commands are save in `drift_workload_generate.sh` file.


## Test

After generating the drifted workload, we mainly run `tmp_execution.sh` to test performance of specific learned index structure.

Consider the long path parameters, we need to first assign the path of the workload and dataset first in `tmp_execution.sh` file, such as that
```shell
# accept two arguments, index and flag
# index: the index of the data structure to be tested
# flag: the flag to indicate the type of the test
#      --through: throughput test
#      --errors: latency test
index=$1
flag=$2

# manually change the data path and workload file base name
data_path="/users/lingze/TLI/data/fb_200M_uint64"
workload_base="/data/lingze/workload/fb_200M_uint64_drift_"

# change the workload file name 
workload_file="workload_ops_200M_0.000000rq_0.000000nl_0.500000i_fix_2m"
```
